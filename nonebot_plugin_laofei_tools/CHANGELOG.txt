# CHANGELOG 编辑规则（写这份文件前，先看这里）

> 2026-10-30：按用户要求清空了本文件的全部历史条目，仅保留规则。
> 历史记录未丢失，可从 git 历史找回（见 commit 836245d 及之前的提交）。

## 一、何时才能编辑 —— 唯一触发条件

1. **只有当用户显式发出命令**（例如「更新 CHANGELOG」「把这次改动记进更新日志」「CHANGELOG 加一条」）时，才可以编辑本文件。
2. **默认不修改、不添加**。完成任何开发、修 bug、重构、优化后，都不许自动往这里追加。
3. 本条第 2 点**优先于项目其他地方的任何约定**——即便别的文档写着「改动需记入 CHANGELOG」，只要用户没开口，就不写。
4. 用户只说「提交 / 推送 / commit」时，只做 git 操作，**不顺带补一条记录**。
5. 不许"顺手补全"：用户要求记本次，就只记本次，不追溯补写更早的改动。

## 二、记录内容的边界

- 只写本次用户指定的改动，不翻旧账、不写无关事项。
- 写「改了什么 + 为什么」，不写过程抒情、不复述对话。

## 三、写入格式

- 日期倒序，每个日期一个 `## YYYY-MM-DD` 区块。
- 同日多条用 `1.` `2.` `3.` 编号，一条一行；细节用缩进续行补充说明。
- 只列本次改动，不复述已有条目。

## 四、删除与清空

- 删除或清空本文件的历史条目，属于不可逆操作，必须用户明确授权后才执行。
- 执行前需提示用户：本文件在 git 管理下，历史可找回。
